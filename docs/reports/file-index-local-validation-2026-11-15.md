# v1.0.7 文件索引改造及本机验证（2026-11-15）

## 实现结果

采用 `meta.json / SVG 文件 → 持久化 SQLite 元数据索引 → SQL 筛选分页 → 按需输出 SVG 文件`。本次修改、迁移和压力测试均在本机，未连接或修改 VPS，也未执行线上部署。发布到 GitHub 不等于已部署。

- SQLite 不再保存 SVG BLOB。SVG 从原文件打开并流式返回，ZIP 逐文件打包；读取时校验索引哈希，拒绝尚未扫描的文件变更。
- 移除常驻的全量公开目录缓存。公开列表先在 SQL 内筛选、排序及分页，每页最多 48 条，再读取展示字段。侧栏最多 30 条，目录分页展示；合集选择改为合集总览入口，避免每次输出几千个选项。
- 持久化文件哈希、大小、时间与库根目录。普通扫描逐个读取 meta.json，未改变的 SVG 复用哈希；仅重建发生变化的合集。完整扫描仍校验全部 SVG，并可修复逻辑索引不一致。
- 旧目录索引自动迁移并回收原 BLOB 空间；损坏的可再生目录索引可重建。runtime.sqlite3 中的账号、设置及业务记录不删除。
- 上传和编辑使用短期暂存，提交后释放；保留原有并发上限、取消与超时保护。管理端完整备份/导入仍有受容量限制的批量内存开销，不等同于公开页面常驻缓存。

主要修改位置：catalog_schema.go（模式及迁移）、public_catalog.go（SQL 查询）、file_assets.go（文件输出）、library.go / library_manifest.go（持久化及增量索引）、archive.go（ZIP 流式读取）、home.html（精简目录入口）。

## 同条件压力测试

Windows 11 本机 WSL2，Linux 6.18，Go 1.26.3。使用同一份素材副本，Docker 限制 1 核、512 MiB、无 swap，GOMAXPROCS=1。对照为 v1.0.6，候选为本次实现；主对比均保持 GOMEMLIMIT=128MiB。原始聚合结果见同名 JSON。

| 指标 | v1.0.6 | v1.0.7 候选 |
| --- | ---: | ---: |
| 首次建索引至健康 | 5.630 秒 | 4.478 秒 |
| 再次启动至健康 | 3.554 秒 | 0.639 秒 |
| SQLite 目录索引 | 40.00 MiB | 8.10 MiB |
| 压测后空闲 10 秒进程 RSS | 85.00 MiB | 36.40 MiB |
| 冷启动进程高水位 RSS | 143.42 MiB | 76.42 MiB |
| 普通 30 请求成功率 | 30/30 | 30/30 |
| 普通请求 P95 | 14.70 ms | 10.84 ms |
| 抽样页面平均 HTML | 134,071 字节 | 16,834 字节 |
| 300 请求、25 请求/秒、250 ms 超时 | 全部 200 | 全部 200 |
| 上述请求 P95 | 13.30 ms | 9.73 ms |
| 上述请求阶段 CPU 时间 | 2.778 秒 | 2.192 秒 |
| 32 客户端持续 20 秒：200 / 503 | 2541 / 32 | 4049 / 27 |
| 持续压力下成功请求 P95 | 258.19 ms | 217.18 ms |

持续压力中的 503 为保留的并发保护快速拒绝；没有 OOM。压力后健康检查全部 200。SVG 下载成功，全量 ZIP 5,129 个条目均通过完整性校验。

额外以 GOMEMLIMIT=64MiB 复测，新版空闲 RSS 36.31 MiB，结果与 128MiB 接近，因此保留默认 128MiB，收益来自减少数据复制和查询开销。GOMEMLIMIT 是 Go 软目标，并非进程 RSS 上限。

这些是单轮本机比较，不是长期线上统计。Docker 的 file cache 按页归属记账，不适合跨容器直接承诺总内存；这里重点比较进程 RSS。WSL 的内核及透明大页设置与 VPS 不同，不能保证线上 Docker 面板也显示 36 MiB。

## 正确性及兼容性验证

- Windows `go test ./...`、`go vet ./...` 通过。
- WSL2 `go test -race ./... -count=1 -timeout=6m` 全部通过，app 包约 163 秒；JS 语法检查通过。
- 临时验证覆盖：热启动复用 SVG、不保存 BLOB、旧 BLOB 索引迁移并回收空间、损坏索引恢复、账号/设置保留、完整扫描修复逻辑索引、130 合集分页及筛选、旧收藏别名、不经扫描的 SVG 修改被拒绝。临时验证代码已在提交前移除，原有正式测试保留并适配文件读取。
- 对真实素材副本仅修改 36kr/meta.json，经管理接口扫描后只有 36kr 的索引更新时间变化，其余 2,722 个合集不变，前台立即显示新标题；测试后恢复原文件并再次扫描。耗时约 1.511 秒，含后台页面渲染。
- 本机实际 Docker 入口运行，业务进程以 UID 10001 执行；桌面和 390px 手机布局、Google 合集两页 48/24 条、合集目录每页 48 条、侧栏搜索与 SVG 显示通过浏览器检查，无控制台错误。
- 压测初次发现 SQLite 对合集可见性 EXISTS 使用全局索引，导致查询缓慢；已增加以 brand_id 开头的覆盖索引并重新完成测试。表格仅采用修复后的结果。

## 发布与上线观察

版本号更新为 1.0.7；通过现有 GitHub 标签流水线构建及发布。上线应另行执行，并先备份 library 与 data。首次启动迁移目录索引会有一次正常 CPU 峰值，后续启动复用索引。线上验证应分别观察进程 RSS、Docker 内存/cache、空闲 CPU、扫描日志及请求错误率，不能用本机数字替代线上观察。保留原有 CPU/并发保护，不以限制资源代替优化。
