# v1.0.6

修复爬虫集中访问导致的 CPU 满载、内存积压和健康检查失效问题。

- 公共目录复用一份元数据快照，数据库变更后更新；避免每个合集请求重新读取、解析和排序全部目录。
- 合集侧栏最多展示 30 条，按需搜索；完整合集总览、分页、产品与图标入口继续保留。
- 动态公共页面及下载请求最多 4 个、SVG 资源独立最多 16 个、后台请求最多 8 个，ZIP 打包最多 1 个；超额立即返回 503 和 Retry-After，避免无界排队。
- 公共数据库查询和下载使用请求取消信号；等待数据库或写锁的客户端断开后及时退出。健康检查使用独立的一秒期限。
- 冷启动省去一次完整探测读取；素材规范化按合集分组 SVG，避免为每个合集遍历整个文件集合。
- Docker 的默认 GOMEMLIMIT 调整为 128MiB，减少扫描时过度 GC。该参数是软目标，不是容器内存上限；已有部署显式配置的值不会被自动覆盖。
- 保留现有 data、library 持久化目录，无需迁移。服务繁忙时出现少量 503 是预期的资源保护行为。

WSL2、Go 1.26.3、1 核 / 512 MiB 容器中的对比测试：同样 300 次短超时抓取，旧版全部超时并触及 512 MiB 上限；新版全部成功，P95 12.35 ms，峰值 114.76 MiB。交叉测试中，旧版仅提高 GC 目标仍然失效，新版保留 32 MiB 仍能通过。

完整方法、限制和逐阶段结果见 [性能修复与压测报告](https://github.com/charley008/icon-svg/blob/v1.0.6/docs/reports/v1.0.6-performance.md)。本版本未自动更新任何线上实例。
